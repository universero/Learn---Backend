## Panic

如数组访问越界，空指针引用等问题只有运行时才能检查到，这些运行时错误都通过panic来抛出
当panic发生时，程序会中断运行，并立即执行该goroutine中defer的函数。随后程序崩溃并输出日志信息，包括panic value和函数调用的堆栈跟踪信息。

虽然panic类似于其他语言的异常，但panic会引起程序的崩溃，因此panic一般用于严重错误，如程序内部的逻辑不一致等。而所有可以被预计的错误都应该使用errror处理而不是panic。
## Recovery

通常情况下，不应该对panic异常进行处理，但有时我们可以从异常中恢复从而在崩溃前做一些补救措施

使用示例如下
```go
defer func() {
	if p := recover(); p != nil {
		err = fmt.Errorf("internal error: %v", p)
	}
}()
```
