## 字符串

Go语言中字符串是不可变的, 拼接字符串事实上创建了一个新的字符串对象, 若代码中存在大量的字符串拼接, 对性能会有严重影响

### 常见拼接方式

- 使用+: 效率低
- 使用fmt.Sprintf(): 效率低, 常用于格式化字符串
- 使用strings.Builder: 效率高, 如果使用Grow预分配内存效率更高
- 使用bytes.Buffer: 效率高
- 使用`[]byte`: 效率高, 指定cap效率更高

### 比较

- strings.Builder 和 +
  字符串是不可变类型, 每次使用+拼接时会产生一个新的字符串, 需要开辟一段新的空间, 空间大小为原来两个字符串之和
  strings.Builder, bytes.Buffer包括[]byted都是以倍数申请的. 每次拼接只需要申请一个增量的空间, 而不是全部都重新申请
- strings.Builder和bytes.Buffer
  `strings.Builder` 和 `bytes.Buffer` 底层都是 `[]byte` 数组，但 `strings.Builder` 性能比 `bytes.Buffer` 略快约 10% 。一个比较重要的区别在于，`bytes.Buffer` 转化为字符串时重新申请了一块空间，存放生成的字符串变量，而 `strings.Builder` 直接将底层的 `[]byte` 转换成了字符串类型返回了回来。

```go
// builder
// String returns the accumulated string.  
func (b *Builder) String() string {  
	return *(*string)(unsafe.Pointer(&b.buf))  
}

// buffer
// To build strings more efficiently, see the strings.Builder type.  
func (b *Buffer) String() string {  
	if b == nil {  
		// Special case, useful in debugging.  
		return "<nil>"  
	}  
	return string(b.buf[b.off:])  
}
```

## 切片

Go的切片是在数组之上的抽象数据类型, 数组类型定义了长度和元素类型, 数组的长度是固定的且作为类型的一部分. 在C语言中数组变量是指向第一个元素的指针, 但Go语言中数组属于值类型, 当作为参数传递时会复制整个数组
切片操纵不会复制数组, 创建新的切片会复用原来的底层数组, 因此操作更为高效

### 陷阱

- 大量内存得不到释放
	- 在已有切片的基础上进行切片，不会创建新的底层数组。因为原来的底层数组没有发生变化，内存会一直占用，直到没有变量引用该数组。因此很可能出现这么一种情况，原切片由大量的元素构成，但是我们在原切片的基础上切片，虽然只使用了很小一段，但底层数组在内存中仍然占据了大量空间，得不到释放。比较推荐的做法，使用 `copy` 替代 `re-slice`。
- 内存回收
	- 在一个元素不用后, 将这个位置置空有利于GC

## range

特性
- 遍历slice时, 在循环开始前会计算一次循环变量, 此后在循环中修改切片长度也不会改变循环次数, nil切片迭代次数为0
- 遍历map时, 删除未迭代的键值对会影响到循环, 创建新的键值对可能遍历到也可能遍历不到
- 遍历channel时, nil的channel会永久阻塞

range会返回每个迭代值的拷贝, 如果结构体较大则性能较差
