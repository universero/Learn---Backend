## 基本概念

- 认证 Authentication: 验证用户的身份
- 授权 Authorization: 授予第三方应用访问用户信息的权限
- 凭证 Credentials: 携带消息的标识媒介

## Cookie

- 定义：服务器发送到客户端并保存在本地的小型文本文件(通常小于4KB)，用于追踪和识别用户状态
- 使用:
	- 服务器: 设置HTTP响应头的Set-Cookie字段，将cookie发送给客户端
	- 客户端: 获取到服务器发送的Cookie后保存在本地，此后的请求中Cookie请求头携带cookie
- 核心属性

| 属性         | 说明                                                         |
| ---------- | ---------------------------------------------------------- |
| name=value | 键值对，必须是字符串类型。<br>- Unicode字符: 需要为字符编码<br>- 二进制数据: Base64编码 |
| domain     | cookie所属域名，默认当前域名，不可跨域，子域名间可共享                             |
| path       | 指定在哪个路径下生效，默认 /                                            |
| maxAge     | cookie失效的时间，正数则在maxAge秒后失效；负数直至关闭浏览器失效                     |
| expires    | 过期时间                                                       |
| secure     | 是否仅使用安全协议传输，默认false                                        |
| htpOnly    | 设置了则只能通过http请求携带，无法通过js获取                                  |
- 作用:
	- HTTP是无状态的协议，cookie用于记录客户端状态
- 优点
	- 简单易实现，浏览器管理
- 缺点
	- 大小有限制，约50个cookie，4KB
	- 安全性问题，(XXS，CSRF)
	- 隐私问题(第三方cookie追踪)，不能存储铭感数据
	- 无法跨域
	- 移动端支持不是很好

## Session

- 定义: 服务器存储用户的会话信息，通过唯一的Session ID和客户端关联
- 使用:
	- 创建: 用户登录后，服务器生成唯一的Session ID并存储(通常redis)
	- 传递: 通过Cookie或URL参数将会话ID发送给客户端
	- 验证: 客户端携带SessionID，服务器查询对应的Session数据验证身份
- 优点:
	- 敏感数据存储在服务器，安全性较高
	- 支持复杂会话管理(如强制下线)
- 缺点:
	- 服务器存储资源占用
	- 分布式环境下需要解决Session共享问题
- 共享方案:
	- session复制: session修改后向其他服务器广播变化
		- 优点: 可容错，各服务器间实时响应
		- 缺点: 增加网络负荷
	- session / IP 绑定: 某个ip的请求定向到同一台服务器上, 将用户和服务器绑定
		- 优点: 简单
		- 缺点: 容错低，当前服务器故障时，session失效
	- session共享: 使用分布式存储, 如redis，虽然增加一次redis访问，但是可以水平扩展，不易丢失
	- session持久化: 存在数据库中，数据库压力大
## Token

- 定义: 服务器生成的凭证，客户端在请求时携带token验证身份，无需再服务器存储会话状态
- 使用: 
	- 服务器生成token并封装相关信息
	- 客户端请求携带token(一般是Authorization字段)
- 优点:
	- 无状态，易扩展
- 缺点:
	- 泄露可能被滥用
	- 撤销困难，如强制下线 (但是应该可以用类似于黑名单的机制，如果在黑名单中不允许操作就能实现)
- refresh token: 存储在数据库中，用于刷新access token，避免重复登录的麻烦
## JWT

- 定义: Json Web Token，一种标准化的token，将数据通过加密算法签名
- 使用: 和token一致, 但是由于额外存储了数据，相比Token减少了对数据库的访问
