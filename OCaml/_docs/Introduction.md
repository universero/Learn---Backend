## The Past of OCaml

从谱系上来看, OCaml是以Lisp祖父的编程语言, 与其他现代语言如Haskell、Clojure、F#等处于同一级

OCaml 源自 Robin Milner 等人在苏格兰爱丁堡计算机科学实验室的工作。他们在 20 世纪 70 年代末和 80 年代初致力于定理证明器的研究。传统上，定理证明器是用 Lisp 等语言实现的。Milner 一直遇到一个问题：定理证明器有时会将不正确的“证明”（即非证明）拼凑在一起，并声称它们是有效的。因此，他尝试开发一种只允许构造有效证明的语言。ML（元语言）就是这项工作的成果。ML 的类型系统经过精心构建，因此使用该语言只能构造有效证明。定理证明器随后被编写为构造证明的程序。最终，这种“经典 ML”演变成了一种成熟的编程语言。

80年代初, ML社区出现了分类, 法国人开发了CAML以及后续的Objective CAML(OCaml), 而英国人和美国人开发了标准ML. 微软与05年推出变体, 名为F#
## The Present of OCaml

OCaml是一种函数式编程语言, 关键是抽象的数学函数. 函数将输入映射到输出. 相同的输入一定产生相同的输出, 也就是说数学函数是无状态的: 它们不会维护任何在函数使用期间持续存在的额外信息或状态. 函数是一等公民: 可以用作输入也可以作为输出. 用函数来表达一切, 可以实现一个简单而统一的编程模型, 比其他语言家族中的过程和方法更容易推理

命令式编程语言(如C、Java)涉及可变状态, 这些状态在执行过程中不断变化.命令通过指定如何计算来破坏性的更改状态. 过程除了产生返回值外, 还可能存在更新的状态的副作用

可变性的妙处在于很容易推理: 机器先做这个, 然后做那个. 可变性的实际情况是, 机器擅长复杂的状态操作, 而人却不擅长理解. 可变性破坏了引用透明性: 即用表达式的值替换表达式而不影响计算结果的能力. 在数学中，对于f(x) ，你可以在任何出现x的地方用y替换。但在命令式语言中，你却不能：f可能会产生副作用，因此在时间t计算f(x)的结果可能与时间t'的结果不同。

人们很容易相信机器只操控单一状态，并且每次只做一件事。计算机系统竭尽全力试图提供这种假象。但这仅仅是一个假象。实际上，状态有很多，分布在线程、核心、处理器和联网的计算机上。而且机器会同时执行许多操作。可变性使得对分布式状态和并发执行的推理变得极其困难。

然而，不变性将程序员从这些担忧中解放出来。它提供了构建正确并发程序的强大方法。与大多数函数式语言一样，OCaml 主要是一种不可变语言。它确实支持具有可变状态的命令式编程，但我们在本书的许多章节中不会使用这些功能——部分原因是我们根本不需要它们，部分原因是为了让你彻底戒掉你可能从未意识到的依赖关系。这种摆脱可变性的自由是 OCaml 能给你带来的最大视角变化之一。
### The Features of OCaml

OCaml 是一种静态类型且类型安全的编程语言。静态类型语言会在编译时检测类型错误；如果检测到类型错误，该语言将不允许程序执行。类型安全语言会限制对哪些类型的数据可以执行哪些类型的操作。实际上，这可以避免很多愚蠢的错误（例如，将整数视为函数），也可以避免很多安全问题：美国计算机应急响应小组 (CERT，一个负责网络安全的政府机构) 报告的入侵事件中，超过一半是由于缓冲区溢出造成的，而这在类型安全语言中是不可能发生的。

有些语言，例如 Python 和 Racket，是类型安全的，但属于动态类型。也就是说，类型错误只能在运行时捕获。其他语言，例如 C 和 C++，是静态类型的，但并非类型安全的：它们会检查部分类型错误，但不能保证所有类型错误都不存在。也就是说，无法保证运行时不会发生类型错误。还有一些语言，例如 Java，则结合使用静态类型和动态类型来实现类型安全。

OCaml 支持许多高级功能，其中一些您以前可能遇到过，而有些可能是新的：
- Algebraic data types: 代数数据类型, 在 OCaml 中，你可以轻松地构建复杂的数据结构，而无需费心处理指针和内存管理。模式匹配（我们很快会学习的一个功能，可以检查数据结构的形状）使它们更加便捷。
- Type inference: 类型推断：您无需在任何地方都写下类型信息。编译器会自动推断出大多数类型。这可以使代码更易于阅读和维护。
- Parametric polymorphism: 函数和数据结构可以跨类型进行参数化。这对于代码复用至关重要。
- GC: 自动内存管理减轻了您的内存分配和释放负担，这是 C 等语言中常见的错误来源。
- Modules: OCaml 通过使用模块，可以轻松构建大型系统。模块用于封装接口背后的实现。OCaml 通过提供操作模块的函数（称为函子），远远超越了大多数使用模块的语言的功能。
### OCaml in Industry

OCaml 和其他函数式语言远不如 Python、C 或 Java 那么流行。OCaml 的真正优势在于语言操作（例如编译器、分析器、验证器、证明器等等）。这并不奇怪，因为 OCaml 是从定理证明领域发展而来的。这并不是说函数式语言在工业界没有被使用。许多工业项目都在使用 OCaml、Haskell 以及其他语言。Yaron Minsky（康奈尔大学 02 届博士）甚至写了一篇关于 OCaml 在金融行业应用的论文。该论文解释了 OCaml 的特性如何使其成为快速构建复杂可运行软件的理想选择。
