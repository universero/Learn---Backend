## 好的关系的设计特点

### 分解

R为关系模式，R1和R2构成R的分解, 即R= R1 ∪ R2

- 有损分解: 将关系拆分，看似有更多的元组，但记录了更少的信息$$r \subset \Pi_{R_1}(r) \bowtie \Pi_{R_2}(r) $$

- 无损分解: 关系拆分后没有信息丢失$$\Pi_{R_1}(r) \bowtie \Pi_{R_2}(r)=r $$
## 使用函数依赖分解

- 满足所有约束的称为该关系的合法实例
- r(R)指的是具有模式R的关系r
- 超键的定义:  给定r(R)，R的一个子集K是r(R)的超键的条件是, 在r(R)的任意合法实例中，对于r的实例中的所有元组对t1,t2总满足, 若t1≠t2，则`t1[K]≠t2[K]`
$$\begin{aligned} \\
&对于关系模式r(R)，令 \alpha \subseteq R 且 \beta \subseteq R \\
&给定一个r(R)的实例，对于该实例中的所有元组对t_1,t_2, \\
&使得若t_1[\alpha]=t_2[\alpha] 则 t_1[\beta]=t_2[\beta] \\ 
&则认为该实例满足函数依赖 \alpha \rightarrow \beta
\end{aligned}$$
如果每个r(R)的合法实例都满足函数依赖 α → β， 则成该函数依赖在模式r(R)上成立

- 平凡的函数依赖: 所有关系都满足
- 函数依赖集F, F+表示集合F的闭包，即能从F推导出的所有函数依赖的集合
- 如果R_1 ∩ R_2在F+中，即要么构成R_1的超键要么构成R_2的超键，则该分解是一个无损分解 

## 范式

### Boyce-Codd范式 BCNF

- 定义（所有依赖项的决定因素都是候选码的一部分）$$
	\begin{aligned}
	&对F^+中所有形如 \alpha \rightarrow \beta 的函数依赖, 下面至少有一样成立 \\
	&\alpha \rightarrow \beta 是平凡的函数依赖 \\
	&\alpha 是模式R的一个超键  
	\end{aligned}$$
- 分解不属于BCNF范式的模式的通用规则:
	$$
	\begin{aligned}
	&令 R 为不属于BCNF的一个模式, 则至少存在一个非平凡的函数依赖 \alpha \rightarrow \beta, 使得\alpha 不是 R 的超键 \\
	&用 (\alpha ∪ \beta ) 和 (R - (\beta - \alpha)) 代替R
	\end{aligned}
	$$

- BCNF不能保证依赖保持

### 第三范式

- 定义$$
	\begin{aligned}
	&对F^+中所有形如 \alpha \rightarrow \beta 的函数依赖, 下面至少有一样成立 \\
	&\alpha \rightarrow \beta 是平凡的函数依赖 \\
	&\alpha 是模式R的一个超键 \\
	&\beta - \alpha 的每个属性A都被包含于R的一个候选键中  
	\end{aligned}$$
- 分解
- 满足BCNF一定满足3NF
- 可以保持函数依赖  

## 函数依赖理论

逻辑蕴含：从给定函数依赖中推导出新的函数依赖
阿姆斯特朗公理:
$$
\begin{aligned}
&自反律: 若\alpha为一个属性集且\beta \subseteq \alpha, 则 \alpha \rightarrow \beta \\
&增补率: 若\alpha \rightarrow \beta成立且\gamma为一个属性集, 则\gamma\alpha \rightarrow \gamma\beta \\
&传递率: 若\alpha \rightarrow \beta, \beta \rightarrow \gamma, 则\alpha \rightarrow \beta \\
&阿姆斯特朗公理推导的附加规则 \\
&合并率: \alpha \rightarrow \beta成立且 \alpha \rightarrow \gamma, 则\alpha \rightarrow \beta\gamma成立 \\ 
&分解率: \alpha \rightarrow \beta\gamma成立, 则\alpha \rightarrow \beta成立且 \alpha \rightarrow \gamma \\
&伪传递率: \alpha \rightarrow \beta成立且\gamma\beta \rightarrow \delta 成立, 则 \alpha\gamma \rightarrow \delta成立
\end{aligned}
$$

### 属性集的闭包

如果 α -> B, 则称属性B被函数α决定。要计算α函数决定的属性集，一种方式是计算出F+，找出所有左侧为α的函数依赖并合并依赖的右侧。
另一种算法(属性闭包算法)更为高效，
```
result := α;
repeat:
	for each 函数依赖β -> γ in F do
		begin
			if β 属于 result then result:=result∪γ;
		end
until (result不发生变化)
```
用途有
- 测试α是否为超键，如果α+包含所有属性则是超键
- 检查beta属于α+，可以检测一个函数依赖是否成立或属于F+

### 正则覆盖

- 如果一个属性删去而不改变函数依赖的闭包，则称该属性是无关的
	- 从左侧移除 ：如果 A ∈ α , 并且 F 逻辑蕴涵 (F - {α -> β}) U {(α - A) -> β} ，则属性 A 在 a 中是无关的 。
	- 从右侧移除 ：如果 A ∈ α 并且函数依赖集 (F - {α -> β}) U {α -> (β - A)} 逻辑蕴涵 F. 则属性 A 在 β 中 是无关的 。
- 定义：Fc是这样的一个依赖集，F逻辑蕴含Fc中的所有依赖，并且Fc逻辑蕴含F中的所有依赖，此外Fc具备如下性质:
	- Fc中任何函数依赖都不包含无关属性
	- Fc中每个函数依赖的左侧都是唯一的
- 计算方法
Fc = F
repeat
	使用合并律将Fc中任何形如α1->β1和α1->β2的依赖替换成α1 -> β1β2
	在Fc中寻找一个函数依赖α->β，它要么在α中要么在β中有一个无关属性/\*需要用Fc而不是F来检测无关属性\*/
	如果找到一个无关属性，则将它从Fc中的α->β中删除
until (Fc不再改变)

可能有多种不同但同等的Fc

函数依赖

对于关系的分解，如果每个子关系的限定的并集与F有相同的闭包，可以认为是保持依赖的分解

验证方式
对F中的每个α -> β都使用下面的过程

result = α
repeat
	for each 分解后的Ri
	t = (result ∩ Ri)+ ∩ Ri
	result = result ∪ t
until(result没有变化)
如果result包含了β的所有属性，则α -> β被保持。测试完所有的依赖则证明是依赖保持的划分

## 分解算法

### BCNF分解

- BCNF的检测: 检查一个关系模式R是否满足BCNF可以做如下简化
	- 为了检查一个非平凡依赖的α->β是否违反BCNF可以计算a+并验证它是否包含了R中的所有属性，即验证是否为R的超键
	- 检查一个R是否属性BCNF，仅需要检查集合F中的依赖是否违反BCNF
- BCNF的分解算法(无损分解但不一定是依赖保持的)
	result := {R};
	done := false;
	while (not done) do
		if (在result中存在一个模式Ri不属于BCNF)
			then begin
				令 α -> β为在Ri上成立的一个非平凡函数依赖，使得α+并不包含Ri，并且α∩β＝Ø;
				result := (result - Ri)∪(Ri-β)∪(α, β) 
			end
		else done := true
