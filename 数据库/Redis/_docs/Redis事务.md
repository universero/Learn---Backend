Redis事务提供了多个命令打包执行的功能, 但是在实际开发中使用的较少

Redis事务不满足原子性与持久性, 且事务中的每条命令都会与Redis服务器进行网络交互, 比较浪费资源

## 使用

```lua
# 开启事务, 此后可以执行多条命令
MULTI
# 命令入队
正常输入命令
# 执行事务
EXEC

# 取消一个事务
DISCARD

# 监听一个key, 当key被其他客户端操作时, 事务不会执行
# WATCH与事务在一个session中, 且被监视的key修改发生在事务内部, 这个事务可以被执行
WATCH key

```

## 问题

- 不保证原子性, 无法回滚
	- 除了出现错误的命令外, 其余命令均会正常执行
- 无法保证事务的持久性
	- 事务执行成功, 也可能因为持久化机制出现问题没法成功持久化
- 通过Lua脚本, 可以将多条命令一次性执行, 一定程度上保证了原子性, 减小了网络开销
	- 但是出现问题之前的语句无法撤销, 出现问题之后的语句不会执行
