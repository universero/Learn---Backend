## 使用批量操作减少网络传输

一个Redis命令的执行可抽象为如下四步
- 发送命令
- 命令排队
- 命令执行
- 返回结果

可以通过减少网络传输次数来减少发送命令和返回结果耗时之和(RTT), 进而有效减小网络开销
此外, 发送命令的socket I/O成本也比较高, 批量操作还可以减少socket I/O成本

### 批量操作方式

- 使用原生批量操作命令, 如MSET, MGET等
	- 但是如果是集群环境, 可能会有点小问题, 因为无法保证所有的key在同一个哈希槽, 批量操作还是需要多次网络传输, 也无法保证原子性
	- 集群环境下, 不同hash槽的批量操作由redis客户端实现
		- 1. 找到 key 对应的所有 hash slot；
		- 2. 分别向对应的 Redis 节点发起 `MGET` 请求获取数据；
		- 3. 等待所有请求执行结束，重新组装结果数据，保持跟入参 key 的顺序一致，然后返回结果。
- pipeline, 流水线, 可以将一批Redis命令封装成一组, 然后被一次性提交到Redis服务器
	- 需要注意空值批量操作的元素个数, 避免网络传输数据量太大
	- 同样如果是集群环境, 无法保证所有key在同一个哈希槽
	- pipeline是非原子操作, 多个pipeline可以以交错方式执行, 且只需要发送一次
